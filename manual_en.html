1. Quick start

You need the gun, its PS2 USB dongle, a powered sensor bar and a Windows PC. The tool does not require PS2 video or a sync connection, but valid X/Y coordinates must arrive from the dongle. Set the gun itself to single-shot mode.

This source kit contains no EXE. For a built release, extract the entire ZIP and run TimeBreakerPCBridge.exe. Keep the _internal folder beside it. The folder release does not require a separate Python installation.
  1. Extract into a writable folder; do not run inside the ZIP.
  2. Open installation/diagnostics from the main window, then click Refresh status. The window does not open automatically and diagnostics run only when requested.
  3. Install WinUSB for the matching dongle using Zadig. Install ViGEmBus for XInput.
  4. Click USB reconnect, then check incoming coordinates in the main window. Reconnecting does not run diagnostics.
  5. Calibrate all four corners with the trigger. Open Output settings and select mappings.
  6. Press F8 to start output and switch to your game. F9 stops output.

Output starts OFF each time. Mouse and XInput options default ON, including off-screen XInput buttons; saved preferences take precedence. Calibration, measurement and driver operations stop output. Output is suppressed while this tool is in the foreground.

2. Language, diagnostics and logs

Initial language follows the Windows display language: Japanese for Japanese Windows, English otherwise. Change Language at the top of the main window. language.json stores the preference. HTML help selects this English guide when the GUI is English. External installers, UAC and Windows messages follow their own language settings.

Opening diagnostics does not initiate a scan. Click Refresh status whenever you need an updated snapshot. Driver installation and USB reconnect do not automatically scan.

3. Install WinUSB with Zadig

  1. Connect the dongle. Open diagnostics manually.
  2. Download and launch Zadig, or select a saved official installer. Network access is required for downloads. The tool verifies a valid Authenticode signature and an exact approved publisher name.
  3. In Zadig choose Options → List All Devices. Identify USB ID 0B9A:016A; do not select by name alone.
  4. Select WinUSB and click Install Driver or Replace Driver. Approve the UAC prompt.
  5. Close Zadig and click USB reconnect. Refresh status explicitly if needed.

A Code 28 device can have an unfamiliar name. If the USB ID differs, do not replace its driver. The sensor bar is not the PS2 dongle.

4. Virtual Xbox 360 / XInput

Install the official ViGEmBus 1.22.0 driver from diagnostics, then restart Windows if requested. ViGEmBus is end-of-life and shared with other controller tools. The app checks the installer signature and publisher before launching it with elevation. No old MSI is bundled or silently installed.

Select XInput output, start output and open joy.cpl (Controller check). Press the gun buttons. An installed Python module alone does not establish that the OS driver or virtual controller works.

5. Four-corner calibration

  1. Keep the powered sensor bar in the intended position and face the display.
  2. Start position calibration. Aim at the yellow top-left target and pull the trigger once.
  3. Repeat for top-right, bottom-right and bottom-left. Coordinates are captured on the trigger press, not by an on-screen capture button.
  4. Confirm the cyan point follows your aim. Red indicates trigger ON. Save settings in Output settings.

X=0 hides the point. Insufficient coordinate range prevents calibration. If Y never changes, examine raw reception and hardware conditions. Calibration transforms coordinates locally; it does not alter gun firmware or PS2 calibration. Reset position alignment or display bounds when needed.

7. PC autofire and measurements

With the gun in single-shot mode, enable PC trigger autofire. Period is 32–5000 ms; press time is 16 ms to period minus 16 ms; start delay is 0–10000 ms. These are software timings and cannot guarantee exact scheduling. This feature does not change receiver firmware or fix PS2 output.

For packet measurements, select single-shot or automatic gun mode and start the 30-second recording: release for 0–5 s, hold for 5–15 s, release for 15–20 s, then repeatedly pull for 20–30 s. Keep the aim steady. Logs describe received packets, not a hardware firmware dump.

9. Uninstall selected drivers

Open diagnostics and select dongle OEM driver registrations and/or ViGEmBus. The tool stops output and USB reading, asks you to confirm the selected scope, then requests elevation. ViGEmBus removal affects other apps using this shared driver.

The elevated process rechecks targets and refuses packages serving unrelated devices or whose bindings cannot be verified. Windows' own WinUSB component, other USB devices, Zadig certificates and Python environments are not removed. Progress is displayed and written immediately to %LOCALAPPDATA%/TimeBreakerPCBridge/diagnostics/uninstall_*.txt; *_launch.txt records startup errors. Restart Windows and explicitly refresh status before reinstalling.

If removal fails, send the removal/startup logs and the GUI error log. Do not assume partial removal is a clean state. You can also use Windows Installed Apps or Device Manager for the specific component.

10. Source setup, build and release

setup_windows.bat creates .venv and installs hash-pinned runtime dependencies plus selected vgamepad files; it does not install OS drivers. start_windows.bat runs source/launcher.py. Source setup accepts x64 Python 3.11 or later.

build_exe_windows.bat uses official Windows x64 Python 3.13.16, recreates the dedicated .build_venv and builds from source. It runs tests, audits bundled components and tests the EXE libraries and Japanese/English GUI. Successful output is release/TimeBreakerPCBridge_v0.2.2_Windows_x64.zip and SHA256SUMS.txt. Only the folder EXE form is distributed. A separate diagnostic console EXE is for build failures and is not included in the public release.

Source and documents belong in the repository; generated binaries belong in Releases. See docs/BUILD_AND_RELEASE.md and docs/MANUAL_VALIDATION.md. CI checks do not replace real USB/controller/driver installation tests. This source kit does not claim those Windows hardware tests have been completed.
